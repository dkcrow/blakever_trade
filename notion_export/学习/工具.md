		以下是这个工作流程的基本步骤：
		1. **从主分支创建新的分支**：每当你开始一个新的任务或特性，你都应该从主分支创建一个新的分支。这样可以确保你的工作不会影响主分支，同时也可以让其他人继续在主分支上进行开发。
			```shell
bash复制
git checkout master# 切换到主分支
git pull origin master# 更新主分支的最新代码
git checkout -b my-feature# 创建并切换到新的分支
			```
		2. **在新分支上进行开发**：在新分支上进行所有的开发工作，包括编写代码、提交更改等。
			```shell
bash复制
# 编写代码...
git add .# 将所有更改添加到暂存区
git commit -m "My changes"# 提交更改
			```
		3. **推送分支到远程仓库**：完成开发后，将你的分支推送到远程仓库，这样其他人就可以看到你的更改。
			```shell
bash复制
git push origin my-feature# 将分支推送到远程仓库
			```
		4. **创建Pull Request**：在GitHub或其他支持Git的平台上，你可以创建一个Pull Request（PR），请求将你的分支合并到主分支。这也是一个很好的机会让其他人对你的更改进行代码审查。
		5. **合并分支**：代码审查完成后，你可以将你的分支合并到主分支。在大多数情况下，你应该使用`-no-ff`选项来保留分支历史，并创建一个合并提交。
			```shell
bash复制
git checkout master# 切换到主分支
git merge --no-ff my-feature# 将分支合并到主分支
git push origin master# 将更改推送到远程仓库
			```
		6. **删除分支**：最后，你可以删除你的分支，因为你已经不再需要它了。
			```shell
bash复制
git branch -d my-feature# 删除本地分支
git push origin :my-feature# 删除远程分支
			```
		这只是一种常见的工作流程，实际的工作流程可能会根据你的团队和项目的具体需求进行调整。

<summary>手机mgba导入存档到电脑vba把卡关的地方解决后再把存档转回手机</summary>
	1.手机gba里 保存游戏(游戏内置的保存而非模拟器带的保存) 导出存档为srm格式的文件a 这个是通用gba保存格式 和模拟器平台的保存无关. 
	2.[Save File Converter](https://savefileconverter.com/#/srm-sav) 把srm转成sav格式 文件a → b
	3.电脑上打开vba, 导入电池存档选项里 导入b, 就能运行之前的gba存档了
	4.把卡关的地方用vba运行过去后游戏内保存一次 导出电池存档得到 sav格式的文件c
	5.继续上面的网站, 把c→ srm格式的文件d
	6.手机gba上运行游戏rom的同时选择加载这个d文件. 就能得到当时电脑上玩的进度了
