一、未来函数检测
这是最致命的问题，没有之一。所谓未来函数，就是你在回测里用了“当时还不知道”的数据 。

检测项	状态	说明
是否开启 set_option('avoid_future_data', True)	✅ / ❌ / ⚠️	聚宽有这个开关，一定要开
是否存在 get_price(..., end_date=today) 且 today 为当日	✅ / ❌	用当天收盘价选当天股票，就是作弊
是否存在 get_price(..., end_date=context.current_dt, frequency='1m') 在盘中调用且未排除当前分钟	✅ / ❌	当前分钟K线的close是这一分钟结束后的价格，盘中无法预知
是否存在 attribute_history(..., count=1, ...) 在盘中调用且未设置 include_now=False	✅ / ❌	这会把当前未完成的K线也算进去
是否存在 get_current_data() 获取的 close 字段用于交易决策	✅ / ❌	盘中close是实时价，不该用来判断是否买入
动量/均线计算是否使用了当日收盘价	✅ / ❌	应该用前一天的数据
财务数据 get_fundamentals 是否指定了 date=context.previous_date	✅ / ❌	财报有披露延迟，不能直接用当天的最新数据
集合竞价 get_call_auction 调用时间是否早于 09:25	✅ / ❌	早于09:25拿不到有效数据
是否使用了未来日期的除权除息数据	✅ / ❌	除权日当天才能用，不能提前
是否在回测中使用了 context.current_dt 作为选股日期，但实际数据需滞后一天	✅ / ❌	很多新手在这翻车
结论：未来函数风险 [极高/高/中/低/极低]

新手最容易犯的就是用今天的收盘价判断今天是否买入。记住一条铁律：你永远不知道下一秒的价格。

二、前视偏差检测
前视偏差和未来函数有点像，但更隐蔽。它指的是你用了“回测当时不存在”的东西。

检测项	状态	说明
静态股票/ETF池是否包含回测起始日尚未上市的品种	✅ / ❌	手工写的池子最容易出这问题
get_index_stocks 是否使用历史日期参数（避免幸存者偏差）	✅ / ❌	应该传当天的日期，不然会拿到现在的成分股
是否过滤了上市日期（info.start_date < = today）	✅ / ❌	没上市的买不进，但你的池子里如果有它就不对
是否过滤了退市/被ST/暂停上市的股票	✅ / ❌	这些票要么买不到，要么风险极大
财务数据是否使用了未发布的财报（报告期 vs 披露期）	✅ / ❌	用Q3财报判断Q1的买卖，这就离谱了
是否使用了未来才发生的重组、分红、送转信息	✅ / ❌	除权信息只能在除权日当天用
止损止盈是否使用了当日最高/最低价（假设能按极端价成交）	✅ / ❌	**你不可能每次卖在最高点
回测起始点是否避开了极端行情（如股灾开始日）	✅ / ❌	故意选一个刚好是底部的起点，就是作弊
是否使用了未来才可获得的行业分类或板块信息	✅ / ❌	行业分类会变，不能拿现在的分类跑历史
结论：前视偏差风险 [极高/高/中/低/极低]

三、过拟合检测
过拟合就是你的策略在回测里表现完美，但一到实操就拉胯。原因是你把参数调得太“适应”历史数据了。

检测项	评估
参数总数（阈值、周期、比例、分位数、权重等）	数值
是否有多层嵌套条件（if-else 分支 > 3层）	✅ / ❌
参数是否经过手工调优（非基于理论或滚动优化）	✅ / ❌
策略逻辑复杂度（简单/中等/复杂/极复杂）	评级
是否在多市场（A股/美股/期货）或多时段（不同牛熊）测试过	✅ / ❌
参数平原是否平坦（参数微小变动对结果影响是否剧烈）	✅ / ❌
极端行情鲁棒性（股灾、熔断、流动性枯竭、黑天鹅）	✅ / ❌
是否使用了未来数据作为参数优化依据	✅ / ❌
样本内/样本外验证是否严格分离	✅ / ❌
策略对随机种子/数据起始点是否敏感	✅ / ❌
结论：过拟合风险 [极高/高/中/低/极低]

一个简单粗暴的判断方法：参数超过5个，而且每个参数都是你手工“试”出来的，那大概率过拟合了。

四、买卖位置合理性检测
你什么时候买、什么时候卖，直接影响回测的真实性。

检测项	状态	说明
买入时间是否在开盘瞬间（09:30前）或集合竞价	✅ / ❌	集合竞价买入假设能按开盘价成交，**未必
买入是否基于“上午涨得好，下午买入”的盘中追涨	✅ / ❌	这种信号衰减很快
卖出是否仅在尾盘（如14:50后集中卖出）	✅ / ❌	尾盘卖出可以避免盘中波动，但不是所有策略都适合
止损触发后是否当日可卖出（T+1限制）	✅ / ❌	A股T+1，今天买的股票今天不能卖
限价单设置是否可能永远无法成交（如挂单价偏离市价太多）	✅ / ❌	挂涨停价买入，**可能买不进
信号衰减（信号产生频率是否低于持仓周期，导致过度交易）	✅ / ❌	一天出三次买卖信号，那就是在刷手续费
是否使用了未来函数作为买卖条件（如“未来N日最高价”等）	✅ / ❌	这是经典的未来函数
交易时间是否避开涨跌停无法成交时段	✅ / ❌	跌停卖不出，涨停买不进
是否考虑了大单冲击（如一次性买入总市值1%以上）	✅ / ❌	小市值股票，你买多了自己就把价格拉上去了
结论：买卖位置不合理风险 [极高/高/中/低/极低]

五、回测与实操一致性检测
回测和实操的差距，主要来自这里。

检测项	状态	说明
滑点设置是否合理	✅ / ❌	小市值0.3%-0.5%，中市值0.2%，大市值0.1%，ETF 0.1%
交易成本（佣金、印花税、最低5元）是否正确	✅ / ❌	佣金万1.5到万3，印花税千1
是否考虑了T+1卖出限制（closeable_amount）	✅ / ❌	今天买的股票不能卖
集合竞价买入是否假设能按开盘价成交	✅ / ❌	实际可能买不进
涨停/跌停是否能在极限价格成交	✅ / ❌	**无法买入/卖出
停牌股票是否自动跳过	✅ / ❌	停牌期间不能交易
小市值/低流动性是否考虑了冲击成本	✅ / ❌	可以设置单笔不超过日成交量的1%
是否使用 order_target_value 自动处理100股整数倍	✅ / ❌	聚宽帮你处理了，但要注意取整误差
资金容量（单笔成交额是否超过股票日均成交的1%）	✅ / ❌	超过1%就会有明显冲击
流动性枯竭应对（跌停无法卖出时是否挂单等待或放弃）	✅ / ❌	**要处理这种极端情况
是否考虑了分红、送转对持仓数量和成本的影响	✅ / ❌	聚宽会自动处理，但要确认
是否设置了 use_real_price 为 True	✅ / ❌	影响价格获取，必须开
是否考虑了不可交易状态（新股上市前5天不设涨跌幅、盘中临停等）	✅ / ❌	这些情况要跳过
结论：回测**一致性风险 [极高/高/中/低/极低]**

六、多次卖出/重复交易检测
这是代码逻辑问题，但很容易导致实操乱下单。

检测项	状态	说明
是否有多个卖出函数同时运行（如止损+止盈+调仓）可能冲突	✅ / ❌	多个函数对同一股票发卖出单
卖出后是否立即从持仓记录中移除（避免重复卖出）	✅ / ❌	没移除的话可能再卖一次（卖空）
止损和止盈是否可能同时触发（导致重复下单）	✅ / ❌	同一根K线同时满足两个条件
调仓时是否先卖后买（避免资金不足）	✅ / ❌	正确的调仓顺序
同一股票是否在短时间内被重复调仓（信号抖动）	✅ / ❌	加个冷却期
是否检查订单状态后再发新订单（避免重复委托）	✅ / ❌	聚宽的order函数会返回订单对象
是否使用 order_target_value 但多次调用同一股票	✅ / ❌	多次调用会多次下单
结论：多次卖出风险 [极高/高/中/低/极低]

改进思路（按优先级）
1. 【必须修复】（不修就别**）

开启 avoid_future_data
所有选股数据用 previous_date
过滤未上市股票
止损逻辑遵守T+1
2. 【强烈建议】（严重影响真实性）

设置合理的滑点（小市值0.3%+）
检查静态池是否有幸存者偏差
加入上市日期过滤
做参数敏感性测试
3. 【建议优化】（提升鲁棒性/可读性）

加注释
拆分函数
加缓存减少API调用
做样本外测试
